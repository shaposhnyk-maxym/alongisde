# M20.1 — Recap: доступність і тригер

## Context

`docs/roadmap.md` M20.1 needs a `Recap(tripId, availableAt)` marker that both devices
compute locally (`tripEndDate + 1 day`, no Firestore) and store in Room, written the moment
the trip's last diary day unlocks (both sides READY), gating Home's "Recap" entry on
`today >= recap.availableAt`.

**Discovered gap vs. the roadmap's own framing:** the roadmap describes hooking into "the
same step that currently writes the unlock state of this day" — but no such write exists.
`resolveDayUnlockState` (`core/domain/diary/DayUnlockState.kt`) is a pure, non-persisted
function recomputed every time `DiaryTimelineState.items` is read; `closeDay()` only ever
writes the caller's own entry and has no idea whether the partner has also closed. "Both
sides closed" is discovered reactively downstream, not written anywhere.

**Resolution (approved by user): the "reactive gate" approach.** `DiaryTimelineContainer`
additionally observes a new `RecapRepository` for the active trip, combined into its
existing trip+entries flow. A new `RecapSchedulingCoordinator` (mirrors the existing
`PlaceContentPullCoordinator` pattern in `feature:places`) fires
`recapRepository.ensureScheduled(tripId, availableAt)` as a side effect when it detects
own+partner READY on `trip.endDate`. The last day's displayed `DayUnlockState` is UNLOCKED
only once the Recap row is actually observed as present — this satisfies the accept
criterion that the last day stays locked until `ensureScheduled` succeeds.

  ```kotlin
          own = diaryDayStatus(ownEntry, trip.endDate, today, ownHasEpisodes),
          partner = diaryDayStatus(partnerEntry, trip.endDate, today, partnerHasEpisodes),
      )
  ```

- New `app/src/commonMain/kotlin/com/alongside/app/home/HomeContainer.kt`:
  ```kotlin
  public data class HomeState(val isRecapAvailable: Boolean = false)

  public class HomeContainer(
      private val authSessionCache: AuthSessionCache,
      private val pairingRepository: PairingRepository,
      private val recapRepository: RecapRepository,
      private val clock: Clock = Clock.System,
  ) : ViewModel(), ContainerHost<HomeState, Nothing> {
      override val container: Container<HomeState, Nothing> = container(HomeState()) { observeRecapAvailability() }

      @OptIn(ExperimentalCoroutinesApi::class)
      private suspend fun Syntax<HomeState, Nothing>.observeRecapAvailability() {
          val uid = authSessionCache.get()?.user?.uid ?: return
          pairingRepository.observeActiveTrip(uid)
              .flatMapLatest { trip -> trip?.let { recapRepository.observeById(it.id) } ?: flowOf(null) }
              .collect { recap ->
                  val today = clock.todayIn(TimeZone.currentSystemDefault())
                  reduce { state.copy(isRecapAvailable = recap != null && today >= recap.availableAt) }
              }
      }
  }
  ```

## Risks / judgment calls (flagged, not blocking)

1. `DiaryTimelineDataSource`'s constructor lands exactly at detekt's `LongParameterList`
   ceiling (8, confirmed in `config/detekt.yml`) — passes, but leaves zero headroom for its
   next dependency.
2. **Home test infra:** `app` has zero existing test source sets. This plan adds a plain
   `commonTest` unit test on `HomeContainer`'s state (no Robolectric/Compose), treating that
   as sufficient for the roadmap's "Юніт/Compose-тест" wording, rather than standing up the
   module's first-ever Compose/Robolectric harness for what's still explicitly a placeholder
   screen. Flag to confirm this reading is acceptable.
3. `DiaryTimelineContainer.maybeScheduleRecap` recomputes `diaryDayStatus` for just the last
   day, duplicating what `DiaryTimelineState.items` already computes for all days via
   `buildDiaryTimelineDays`. Intentional (keeps `items` non-suspend/pure) but is accepted
   duplication, not reuse.
4. The exact `awaitState()` call count/ordering in the new `DiaryTimelineContainerTest` case
   (criterion 6) needs to be pinned down empirically once written — depends on how many
   emissions the fake's `combine`/`flatMapLatest` chain actually produces.
